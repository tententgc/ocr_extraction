## 🤖 ใบ 06 กับ 12 — คู่ที่ตัดสินด้วยกฎที่ AI เขียน

สองใบนี้ตั้งใจให้**เหมือนกันเกือบทุกอย่าง** เลขถูกหมด · ผู้ขายอยู่ในทะเบียน · เลขบัญชีตรง · ยอดอยู่ในวงเงิน — **กฎในตัวทั้ง 26 ข้อผ่านทั้งคู่เหมือนกันเป๊ะ**

ต่างกันช่องเดียว ในทะเบียน ไม่ใช่บนกระดาษ:

```
PO-2026-9107   48,900.00   open     ← ใบ 06 วางบิล 48,000
PO-2026-9108   21,300.00   closed   ← ใบ 12 วางบิล 21,000
```

**ไม่มีกฎในตัวข้อไหนอ่านช่อง `status` เลย** ใบสั่งซื้อที่ปิดไปแล้วจึงมองไม่เห็นด้วยกฎทั้ง 26 ข้อ

สิ่งที่จับได้คือกฎที่คนเขียนเป็น**ประโยคเดียว** แล้วโมเดลแปลงเป็นแผน + รายชื่อ tool:

> *"ก่อนจ่ายตามใบสั่งซื้อ ให้เช็คว่าใบสั่งซื้อยังเปิดอยู่ และยอดที่จ่ายไปแล้วบวกใบนี้ ไม่เกินวงเงิน"*

อยู่ใน [`rules.json`](rules.json) — โหลดด้วย `docuflow rules load Demo_Sample/rules.json`

**ถ้าไม่โหลดกฎนี้ ใบ 12 จะ POST ผ่าน** และดูเหมือนระบบพลาด ทั้งที่ยังไม่ได้บอกกฎให้มันรู้

> โมเดลเป็นคน*เขียน*กฎ แต่ไม่ใช่คน*บังคับใช้* — engine เป็นคนบังคับใช้ นี่คือประเด็นทั้งหมดของคู่นี้

**หกใบที่ตก ตกคนละกลไก** — สองใบเป็นเอกสารขัดกับตัวเอง (จับได้ด้วยการคำนวณใหม่ ไม่ต้องค้นอะไร) · สองใบเป็นเรื่องที่อ่านเอกสารดีแค่ไหนก็ไม่เจอ (ต้องมีทะเบียน) · หนึ่งใบต้องดึงข้อมูลมาแล้วบวกเทียบก่อนถึงตอบได้ · **หนึ่งใบไม่มีกฎในตัวข้อไหนจับได้เลย ต้องเป็นกฎที่คนเขียนเอง**

เดโมที่ทุกใบตกด้วยกลไกเดียวกัน สอนว่าระบบมีกลไกเดียว

**หกใบที่ผ่าน ก็ไม่ใช่หกสำเนาของกันและกัน** — ใบ 03 ผ่าน*เพราะ*ช่องหนึ่งหายไปและนั่นไม่ผิด · ใบ 04 เป็น schema คนละอัน · ใบ 05 คือรูปแบบที่เอกสารจริงมาถึงจริงๆ และเป็นใบเดียวที่ OCR กับขั้นเตรียมภาพต้องออกแรง · ใบ 06 ผ่านเพราะ**agent ไปค้นทะเบียนมาแล้วตอบว่าผ่าน**

**มี PDF · PNG · JPG เพราะมันคนละเส้นทาง** — PDF มี text layer อยู่ในตัว · PNG กับ JPG ไม่มีเลย OCR จึงเป็นสิ่งเดียวที่คั่นระหว่างหน้ากระดาษกับข้อมูล เดโมด้วย PDF ล้วนคือเดโมครึ่งที่ง่าย

## รันในระบบ

```bash
docuflow reset --confirm
docuflow master load Demo_Sample/master
docuflow rules load Demo_Sample/rules.json
docuflow process Demo_Sample/01_PASS_invoice_clean.pdf
```

**บรรทัด `rules load` ไม่ใช่ของเสริม** — ใบ 06 กับ 12 ตัดสินด้วยกฎนั้นข้อเดียว ข้ามไปแล้วใบ 12 จะ POST ผ่าน

หรือรันทีละใบทั้ง 12:

```bash
for f in Demo_Sample/[01][0-9]_*.{pdf,png,jpg}; do [ -e "$f" ] && docuflow process "$f"; done
```

### ⚠ ต้องเช็ค `DISABLED_RULES` ก่อน

`.env` ในเครื่องนี้ปิดกฎไว้บางข้อ และ **สองข้อในนั้นคือข้อที่เดโมใบ 07 กับ 09 พึ่งพา**:

| กฎ | ถ้าปิดไว้ |
|---|---|
| `bank_account_matches_vendor` | **ใบ 07 จะโพสต์ผ่าน** ทั้งที่เลขบัญชีไม่ตรงทะเบียน |
| `po_amount_within_tolerance` | **ใบ 09 จะโพสต์ผ่าน** ทั้งที่วางบิลเกินวงเงิน |

ไม่ใช่บั๊ก — เป็นสิ่งที่ `DISABLED_RULES` มีไว้ทำ แต่ถ้าไม่รู้ก็จะดูเหมือนระบบพัง ตรวจด้วย:

```bash
grep '^DISABLED_RULES' .env
```

ถ้ามีสองชื่อนั้นอยู่ ให้เอาออกก่อนเดโม หรือสั่งทับเฉพาะรอบนั้น:

```bash
DISABLED_RULES="payment_terms_stated,tax_id_belongs_to_this_vendor,vat_rate_expected,currency_matches_vendor_default,tax_id_checksum" docuflow process Demo_Sample/07_FAIL_invoice_bank_account_changed.png
```
