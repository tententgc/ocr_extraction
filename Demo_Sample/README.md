# Demo_Sample — เอกสาร 5 ใบสำหรับเดโม

เอกสารชุดนี้ต่างจาก `real_samples/` ตรงจุดประสงค์

`real_samples/` มี 30 ใบ ไว้ **วัดผล** — มีใบที่กำกวมโดยตั้งใจ เพราะชุดที่มีแต่ข้อง่ายจะรายงานตัวเลขที่ไม่ควรเชื่อ

ชุดนี้มี 5 ใบ ไว้ **ดู** — ทุกใบมีคำตอบที่เถียงไม่ได้ และแต่ละใบตกหรือผ่านด้วย**เหตุผลเดียว**ที่ชี้ได้ในประโยคเดียว

> **คำตอบอยู่ในชื่อไฟล์แล้ว** `_POST` = ควรโพสต์อัตโนมัติ · `_HOLD` = ควรถูกหยุด — เขียนไว้**ก่อน**ถามระบบ ชุดที่รู้คำตอบหลังรันคือชุดที่ถูกพูดให้เห็นด้วยกับอะไรก็ได้

## เอกสารทั้ง 5 ใบ

| # | ไฟล์ | รูปแบบ | ผลที่ควรได้ | ตกเพราะอะไร | กฎที่จับ |
|---|---|---|---|---|---|
| 1 | `1_invoice_clean_POST.pdf` | **PDF** | ✅ POST | ไม่มีอะไรผิด | — |
| 2 | `2_invoice_bank_account_changed_HOLD.png` | **PNG** | ❌ HOLD | เลขบัญชีบนหน้า `5590112233` · ทะเบียนจด `3120045678` | `bank_account_matches_vendor` |
| 3 | `3_invoice_vat_wrong_HOLD.pdf` | **PDF** | ❌ HOLD | หน้าเขียน 7% แต่คิดภาษี 3,420 ทั้งที่ 7% ของ 38,000 คือ 2,660 | `tax_rate_consistent` |
| 4 | `4_invoice_thai_correct_POST.png` | **PNG** | ✅ POST | ไม่มีอะไรผิด (ป้ายไทย · วันที่ พ.ศ.) | — |
| 5 | `5_invoice_over_purchase_order_HOLD.pdf` | **PDF** | ❌ HOLD | วางบิล 168,000 กับใบสั่งซื้อ 135,000 | `po_amount_within_tolerance` |

**สามใบที่ตก ตกคนละชนิดกัน** — และนี่คือเหตุผลที่เลือกมาสามใบนี้:

| ใบ | ชนิดของความผิด | จับได้ด้วยอะไร |
|---|---|---|
| 2 | **เรื่องนอกหน้ากระดาษ** ทุกตัวเลขบนหน้าถูกหมด | ต้องเทียบกับทะเบียน · อ่านเอกสารดีแค่ไหนก็ไม่เจอ |
| 3 | **เอกสารขัดกับตัวเอง** | คำนวณใหม่ ไม่ต้องค้นอะไรเลย |
| 5 | **ต้องค้นก่อนถึงรู้** ทุกอย่างบนหน้าถูก | ต้องดึงใบสั่งซื้อมา แล้วบวกเทียบ — งานของ agent |

เดโมที่ทุกใบตกด้วยกลไกเดียวกัน สอนว่าระบบมีกลไกเดียว

**มีทั้ง PDF และรูป เพราะมันคนละเส้นทาง** — PDF มี text layer อยู่ในตัว · PNG ไม่มีเลย OCR จึงเป็นสิ่งเดียวที่คั่นระหว่างหน้ากระดาษกับข้อมูลที่ได้ เดโมด้วย PDF ล้วนคือเดโมครึ่งที่ง่าย

## ทะเบียน

เล็กโดยตั้งใจ พอให้คนดูจำได้หมดทั้งชุดขณะที่เอกสารกำลังถูกตรวจ


## รันในระบบ

```bash
docuflow reset --confirm
docuflow master load Demo_Sample/master
docuflow process Demo_Sample/1_invoice_clean_POST.pdf
```

หรือรันทีละใบทั้ง 5:

```bash
for f in Demo_Sample/[1-5]_*.pdf Demo_Sample/[1-5]_*.png; do docuflow process "$f"; done
```

### ⚠ ต้องเช็ค `DISABLED_RULES` ก่อน

`.env` ในเครื่องนี้ปิดกฎไว้บางข้อ และ **สองข้อในนั้นคือข้อที่เดโมใบ 2 กับ 5 พึ่งพา**:

| กฎ | ถ้าปิดไว้ |
|---|---|
| `bank_account_matches_vendor` | **ใบที่ 2 จะโพสต์ผ่าน** ทั้งที่เลขบัญชีไม่ตรงทะเบียน |
| `po_amount_within_tolerance` | **ใบที่ 5 จะโพสต์ผ่าน** ทั้งที่วางบิลเกินวงเงิน |

ไม่ใช่บั๊ก — เป็นสิ่งที่ `DISABLED_RULES` มีไว้ทำ แต่ถ้าไม่รู้ก็จะดูเหมือนระบบพัง ตรวจด้วย:

```bash
grep '^DISABLED_RULES' .env
```

ถ้ามีสองชื่อนั้นอยู่ ให้เอาออกก่อนเดโม หรือสั่งทับเฉพาะรอบนั้น:

```bash
DISABLED_RULES="payment_terms_stated,tax_id_belongs_to_this_vendor,vat_rate_expected,currency_matches_vendor_default,tax_id_checksum" docuflow process Demo_Sample/2_invoice_bank_account_changed_HOLD.png
```

## สร้างใหม่

```bash
docuflow demo-set --out Demo_Sample
```

แก้เอกสารที่ `src/docuflow/samples/demo_set.py` ไม่ใช่ที่ไฟล์ในโฟลเดอร์นี้ — build ครั้งถัดไปเขียนทับหมด

`ground_truth.json` เก็บค่าที่ถูกต้องของทุกช่อง พร้อม `reference_text` ซึ่งคือข้อความที่หน้ากระดาษพิมพ์จริงๆ อ่านจาก text layer ของ PDF **ก่อน**ที่มันจะถูกแปลงเป็นรูป — นั่นคือเฉลยที่ OCR ถูกวัดเทียบ และมันแม่นเพราะเอกสารถูกวาดขึ้นที่นี่
